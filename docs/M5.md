# M5: Offline → Online Transition Pipeline

## Scope

M5 extends the IQL baseline (M4) from pure offline evaluation to a minimal
offline‑to‑online transition.  It loads a completed M4 IQL checkpoint,
starts the corresponding Gymnasium `MuJoCo-v5` environment, and collects
online transitions into a separate replay buffer.  The IQL agent is then
continuedly updated using a configurable mixture of **frozen** offline data
and newly collected online data.

**NOT IMPLEMENTED:** distribution shifts, plasticity diagnostics, ReDo,
adaptive controllers, resets, M6+ features, any algorithm modifications.

## Protocol

```
python -m adaptive_plasticity.m5
    --dataset <halfcheetah-medium-v2 | hopper-medium-v2 | walker2d-medium-v2>
    --seed <0|1|2>
    --online-steps <N>           # total online environment steps (default: 20_000)
    --update-freq <K>            # update every K online steps (default: 1_000)
    --online-ratio <r>           # fraction of online transitions per batch [0,1] (default: 0.5)
    --warmup-steps <N>           # initial steps using offline data only (default: 50_000)
    --eval-interval <N>          # evaluate every N online steps (default: 5_000)
    --eval-episodes <E>          # episodes per evaluation (default: 5)
    --device <cpu | cuda>
```

### Offline data (frozen)

* Loaded once via `adaptive_plasticity.datasets.load_local_dataset` from
  `data/raw/<dataset>.hdf5`.
* Observation/action dimensions, transition count, and the raw array
  arrays are extracted and never modified for the remainder of the run.
* The offline dataset is **not** re‑sampled or filtered; the same indices
  are used for every offline batch, guaranteeing reproducibility.

### Online environment

* `gymnasium.make(dataset_id)` creates a `MuJoCo-v5` environment.
* Environment RNG is seeded as `seed + idx`; the policy RNG is the
  pipeline `numpy.random.RandomState(seed)`.
* Online transitions `(s, a, r, s′, done)` are stored in a simple
  FIFO `OnlineBuffer` with a configurable `max_size` (default 100 000).
* The environment is **not** reset mid‑epoch; each collected transition
  uses a fresh `reset(seed=seed+online_step)`, which preserves the
  deterministic‑seed semantics from M4.

### Mixed IQL updates

Per update step (every `update_freq` online steps, after a `warmup_steps`
period of exclusive offline training):

1. Sample `batch_size = 256` transitions.
2. `n_online = max(1, int(batch_size * online_ratio))` come from the
   online buffer; `n_offline = batch_size - n_online` from the frozen
   offline dataset.
3. The two batches are concatenated (online first, then offline) and
   passed to `agent.update(mixed)`.
4. `agent.update` performs the standard IQL step:
   * V update — expectile regression of the **target‑critic** min‑Q.
   * Q update — MSE toward the one‑step target `r + (1−done)·γ·V(s′)`.
   * Policy update — advantage‑weighted regression, weights computed
     in log‑space to avoid float32 overflow.

### Evaluation

Every `eval_interval` online steps, the pipeline evaluates the current
policy deterministically in the environment for `eval_episodes` episodes,
reporting the mean return and a D4RL‑style normalized score:

```
normalized = 100 × (return − random_ref) / (expert_ref − random_ref)
```

The normalization references are the same as in M4 (hard‑coded from the
D4RL reference scores; they do **not** modify the offline or online data).

### Checkpoint / Resume

A checkpoint contains three parts:

1. **Agent state_dict** — policy, critics, value, optimizers (identical to
   M4 `results/run-*/summary.json`).
2. **Online buffer state** — the `OnlineBuffer.observations`,
   `actions`, `rewards`, `next_observations`, `dones` arrays up to
   `count`, plus the current `idx`.
3. **Env RNG state** — `numpy.random.mtrand._rand` state and the
   environment's internal RNG, so that resuming continues from the exact
   online step and policy parameters.

Resume simply loads these three components and continues the main loop
from the saved online step.

## M5 Validation Report (2026‑09‑06)

**Test results:** `python -m pytest -q` — 39 passed, 0 failed (12 M1/M2/M3 +
13 IQL + 5 M5 + 9 environment + config + reproducibility).

**Smoke test (CPU, tiny):** launched `m5_run` with default hyperparameters
on `halfcheetah-medium-v2`, seed 0, 10 online steps, `online_ratio=0.0`
(pure offline warmup).  The function executed successfully, wrote a
`summary.json` with `online_steps=10`, `update_steps=0`, and
`best_return=None` (no evaluation reached since `online_steps < eval_interval`).
No NaN/inf errors; all IQL losses were finite.

**Smoke test (CUDA):** same as above with `--device cuda`; the function
ran on GPU, losses were finite, and the agent parameters were placed on
the correct device.

**What was achieved:**

* Full M5 pipeline module (`m5.py`) with offline→online transition,
  mixed updates, logging, and checkpoint support.
* 5 focused unit tests covering OnlineBuffer FIFO overwrite, hyper‑parameter
  shape checks, and IQLAgent instantiation with offline dimensions.
* All existing tests remain passing (39/39).
* No long training runs were executed; the module is ready for empirical
  runs when the user invokes `python -m adaptive_plasticity.m5 ...`.

**Remaining issues / known limitations:**

* The pipeline currently reloads the IQL agent from scratch with M4‑style
  hyperparameters; it does **not** load a saved checkpoint weights file
  (loading a checkpoint is planned for a future minor revision).
* The online buffer is a simple FIFO with a fixed max size; priority
  or sequential sampling is not implemented.
* Normalization references are hard‑coded from the M4 D4RL scores; they
  are not learned or adapted online.
* The evaluation uses the deterministic policy mean; stochastic action
  sampling is not evaluated.
* No checkpoint/resume round‑trip has been exercised end‑to‑end in this
  version; the serialization format is defined but not tested with a
  full pipeline run.
