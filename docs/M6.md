# M6: Plasticity Diagnostics

## Overview

M6 implements minimal, research-grade plasticity diagnostics for the IQL/M5 pipeline to measure learning dynamics during offline→online adaptation. Diagnostics are logged at configurable intervals via `DiagnosticsLogger` and work with existing IQLAgent code without modifying M4.

## Core Diagnostics Functions

| Function | Description |
|---|---|
| `param_magnitudes(agent)` | L2 norm of all trainable parameters (policy, critic, value) |
| `gradient_magnitudes(agent)` | Magnitudes of gradients for all trainable parameters |
| `representation_change(agent, old_agent)` | Mean cosine similarity of parameter vectors (policy/critic/value) |
| `performance_change(returns_before, normalized_before, returns_after, normalized_after)` | Mean/first-delta changes in returns and normalized returns |
| `activation_dormancy(policy, eps)` | Fraction of parameters near-zero (absolute value < eps) |
| `DiagnosticsLogger(log_interval)` | Logs diagnostics at specified steps; stores history |
| `snapshot_diagnostics(agent, old_agent, ...)` | Capture a single diagnostics snapshot |

## Usage Example

```python
from adaptive_plasticity.m6 import (
    DiagnosticsLogger, snapshot_diagnostics,
    param_magnitudes, gradient_magnitudes,
    representation_change, activation_dormancy
)
from adaptive_plasticity.iql import IQLAgent

# Log diagnostics at every 10th step
logger = DiagnosticsLogger(log_interval=10)

# During training loop:
diagnostics = logger.maybe_log(step, agent, returns_before, normalized_before, returns_after, normalized_after)

# Or take a single snapshot:
diag = snapshot_diagnostics(agent, old_agent,
                            returns_before=[1.0], normalized_before=[0.5],
                            returns_after=[2.0], normalized_after=[0.6])
```

## Diagnostics Intervals

- `DiagnosticsLogger(log_interval=100)` logs diagnostics at steps 100, 200, 300, ...
- `maybe_log(step, agent)` returns a dict of diagnostics if `step % log_interval == 0`, otherwise `None`
- Internal counter tracks the most recent logged step for representation change computation

## Diagnostic Metrics

- **param_magnitudes**: Dict mapping `policy.{name}`, `critic.{name}`, `value.{name}` → float (L2 norm)
- **gradient_magnitudes**: Dict mapping `policy.{name}`, `critic.{name}`, `value.{name}` → float (gradient norm, finite when gradients exist)
- **representation_change**: Dict with keys `policy`, `critic`, `value` → float in [0, 1] (cosine similarity; 1 = identical, 0 = orthogonal)
- **activation_dormancy**: Float in [0, 1] or NaN (fraction of parameters with |weight| < eps)
- **performance_change**: Dict with `return_mean_delta`, `return_first_delta`, `normalized_mean_delta`, `normalized_first_delta` → float or NaN

## Design Principles

- **Minimal**: Only measures essential plasticity dynamics; no speculative metrics
- **Reproducible**: All metrics are deterministic given the same agent state
- **Configurable intervals**: `DiagnosticsLogger` intervals are fully configurable
- **No M4 modifications**: Reuses existing IQLAgent; no M4 code changes required
- **Research-grade**: Suitable for measuring learning dynamics during offline→online adaptation

## M7: ReDo Plasticity-Preservation Baseline (Planned)

M7 adds a Representation Distribution Optimization (ReDo) regularizer that constrains policy activation drift during offline→online adaptation. See `src/adaptive_plasticity/m7.py` and `tests/test_m7.py` for implementation details. Not yet integrated into the default IQL update flow; available as a drop-in regularizer for research use.

**Fix note**: The original implementation had a degenerate ``n_samples=1`` case where activation normalization collapsed all features to zero, making the regularizer insensitive to policy weights. The fix uses ``n_obs=32`` synthetic observations for statistics estimation, so the regularizer now properly distinguishes between policies (identical policies → ~0, different policies → >0).

## M8: Distribution Shifts (Planned)

M8 adds configurable distribution shifts that vary in magnitude/type during the online phase of offline→online adaptation. Shifts are applied **only to the online phase**; the offline D4RL data is completely unchanged. Two shift types are provided:

* ``obs_noise``: Adds bounded Gaussian noise to observations after the shift step.
* ``reward_scale``: Multiplies rewards by a severity-controlled factor after the shift step.

The ``DistributionShiftOrchestrator`` fires once at a configured ``shift_step`` and then remains active for the rest of the run. ``shift_step=0`` means no shift. Shifts are deterministic given the pipeline seed and are compatible with existing M6 diagnostics.

## M9: Fixed vs Random vs Adaptive Intervention Controls (Planned)

M9 adds intervention controls for the offline→online RL setting, enabling controlled comparison of different intervention strategies:

* **Fixed intervention**: The same transformation fires once at ``shift_step`` and remains active. Baseline for comparison.
* **Random intervention**: At each online step after ``shift_step``, the transformation fires with a fixed probability derived from ``severity``. Stochastic control.
* **Adaptive intervention infrastructure** (M10): Rule-based controller that adjusts intervention strength based on online M6 diagnostics. Uses only online-available information, has explicit [0,1] bounds, and is deterministic given a fixed seed.

Each intervention type records diagnostics (intervention type, shift step, severity, and type-specific fields) enabling systematic comparison across conditions.

M9 is compatible with existing M6 diagnostics and M8 distribution shifts. See `src/adaptive_plasticity/distribution_shifts.py` and `tests/test_m9.py` for implementation details.

## M10: Adaptive Plasticity Controller

M10 implements an adaptive plasticity controller that dynamically adjusts intervention strength based on online diagnostics from the M6 diagnostics module.

### Controller Design

The ``AdaptivePlasticityController`` is a rule-based (not learned/meta-RL) controller that:

* **Uses only online information**: Takes M6 diagnostics as input - ``repr_change``, ``perf_change``, ``activation_dormancy``, and ``param_magnitudes`` - all available at decision time with no future information.
* **Explicit bounds**: Intervention strength is always clipped to ``[min_severity, max_severity]`` subset of ``[0, 1]``.
* **Deterministic**: Given the same seed, produces identical output for identical inputs.
* **Provenance logging**: Every decision and diagnostic is logged for full traceability.
* **Tunable severity weights**: Weights (``repr_weight``, ``perf_weight``, ``dorm_weight``, ``mag_weight``) are grounded in the plasticity hypothesis:
  - ``repr_weight`` (default 0.4): Representation change drives adaptation
  - ``perf_weight`` (default 0.4): Performance change drives adaptation
  - ``dorm_weight`` (default -0.2): High dormancy reduces intervention strength
  - ``mag_weight`` (default -0.1): Large parameter magnitudes reduce intervention strength

### Interface

```python
from adaptive_plasticity.distribution_shifts import AdaptivePlasticityController

controller = AdaptivePlasticityController(seed=42, repr_weight=0.4, perf_weight=0.4)

# At each update_freq steps, gather M6 diagnostics and update:
diag = {
    "repr_change": 0.5,     # from M6 representation change diagnostic
    "perf_change": 0.1,     # from M6 performance change diagnostic
    "activation_dormancy": 0.2,  # from M6 activation dormancy diagnostic
    "param_magnitudes": {...},  # from M6 param magnitudes diagnostic
}
strength = controller.update(diag)  # returns float in [min_severity, max_severity]

# Apply the strength to modulate intervention severity (in M5 pipeline)
```

### Scientific Principles

- **Clear separation of inputs, control action, and measured outcomes**:
  - *Inputs*: M6 diagnostics (online-available, no future info leakage)
  - *Control action*: Intervention strength in [0,1]
  - *Measured outcomes*: Environment returns, policy performance (separate, no leakage)
- **Rule-based adaptation**: Fixed weighting scheme, not learned, for interpretability
- **Explicit bounds**: Prevents runaway intervention strength
- **Deterministic given seed**: Enables reproducible research
